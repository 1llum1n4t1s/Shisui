# おまかせで適用される通信と電源の設定

[おすすめの使い方](workflow.md)から移した、適用される設定の内容です。

- PC 全体の TCP ペーシングを `always` にします。選択 NIC の媒体で分けず、送信を平滑化してキュー圧を抑える機構を優先します。BBR2 は必須ではありません。有線の比較計測では中央値の一貫した改善は確認できず、遅延改善量は保証しません。
- TCP 設定を初期化したうえで、BBR2・TCP 損失回復（RACK/TLP）・RSS・ECN・timestamps・Fast Open と fallback を明示的に有効化し、RSC を無効化します。既定値への回帰より低遅延を優先する方針です。OS の UDP URO/USO は既定化し、対応する選択 NIC の URO は無効化します。大量受信時の CPU 負荷が増え、受信速度が下がる場合があります。
- 旧 ACK/Nagle 設定を初期化したあと、選択 NIC の `TcpAckFrequency` を DWORD の 1 にし、読み戻して確認します。受信 1 セグメントごとに ACK を返す設定です。ただし、上りが 10Mbps 未満と 30 日以内に計測済みの回線では、この設定を行わず Windows の既定にします。計測がない、古い、回線を確認できない場合は従来どおり 1 です。おまかせ高速化設定から計測は始めません。ゲームや ping の改善量は未測定です。
- TCP の接続要求の初回再送を 1 秒、再送回数を 4 回（計 31 秒）にします。接続を断念するまでの時間は、Windows の既定値（3000ms・2 回なら 21 秒、1000ms・4 回なら 31 秒。どちらかは未確認）以上です。通常の通信の遅延（RTT）を短くする設定ではなく、接続要求が失われたときの再試行を早めるものです。手動の「既定値に戻す」は従来どおり 3000ms・2 回です。
- ECN は対応経路での輻輳通知、timestamps は RTT 計測、Fast Open は対応アプリ・接続先での TCP 通信開始の短縮に使います。UDP ゲームの ping 低下は保証しません。適用後は ECN・timestamps（Internet）と Fast Open の有効状態も確認します。
- 選択した物理 NIC に[ゲーム向け設定](gaming-nic-notes.md)を適用します。
- 現在の電源プランの PCI Express 省電力を電源接続時（AC）だけオフにし、Wi-Fi を最大パフォーマンスにします。バッテリー時の値と他の電源プランは変更しません。PCI Express 機器全体に影響し、消費電力・発熱が増える場合があります。Wi-Fi の変更前の値は保存され、同じ電源プランを選んでメンテナンスから復元できます。

採用理由と適用条件は[設計文書](../../DESIGN.md#低遅延を優先する設定方針)を参照してください。
