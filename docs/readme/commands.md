# おまかせ高速化設定の操作内容

[おすすめの使い方](workflow.md)から移した、実行される処理の詳細です。

- 最初に IPv4・IPv6 のスタックをリセットします。固定 IP・静的経路・DNS などの退避・復元は行いません。保存キーで管理者の削除権限だけが不足する場合は、対象キーの権限を限定して補完します。
- リセット後、選択した NIC の DHCP アドレスを再取得し、DNS を Cloudflare の標準 DNS へ変更して DoH を有効にします。DHCP で取得していないアドレスは対象外です。再取得に失敗した場合は実行ログを確認してください。
- DoH 登録の欠落・不整合を修復し、既存の平文 DNS への切り替え禁止設定を維持します。証明書や Tailscale の設定は初期化しません。登録値の確認は暗号化通信の成功を保証しません。
- 設定後に DNS キャッシュを再構築し、名前解決・名前解決ポリシー・hosts・今回の DNS エラーを確認します。失敗や確認不能は実行結果に残します。設定変更前に再確認待ちと起動指紋を保存できなければ処理を開始しません。確認待ちが残った場合は、PC 再起動後のアプリ起動時に再検証し、正常確認と解除の保存が成功した場合だけ待ちを解除します。保存に失敗した場合の自動再確認は保証しません。
- Winsock は全登録を確認し、通信機能の拡張（LSP）がない場合だけリセットします。LSP がある場合は保護して省略し、確認できない場合は未実施のエラーを表示します。WinHTTP の自動プロキシキャッシュの消去を要求しますが、保存済みプロキシ設定は変更しません。
- 変更の前に、確立済みの IPsec 接続状態を破棄します。IPsec の規則は変更しません。WINS を利用している場合は、DHCP 再取得後に NetBIOS 名を再登録します。対象がなければ省略し、確認・実行の失敗はログに残します。
- 切断済みデバイスの登録と接続名の連番を整理します。PC 全体のルート表のクリアは行いません。
- 設定の反映には PC の再起動が必要です。

リセットの一部が失敗しても、処理が終了していればエラーを実行ログへ残して再設定を続けます。タイムアウトなどで終了を確認できない場合は、後続の変更を停止します。PC を再起動してから、おまかせ高速化設定をやり直してください。

MTU とルーターの設定は自動変更しません。適用結果は実行ログで確認できますが、速度や遅延の改善を保証するものではありません。変更範囲は[設計文書](../../DESIGN.md#ネットワーク操作)を参照してください。
