# OS コマンドと API の契約

おまかせと手動メンテナンスが、netsh・Winsock・WinHTTP・IPsec・WINS・DHCP の結果をどう判定するかを定めます。

## IP スタックのリセット

- 退避・復元は行わず、以前の固定 IP・静的経路・DNS や OS 全体の調整値を再適用しません。IPv4・IPv6 のスタックを先にリセットし、各 reset の前に、対応する NSI 保存キー（IPv4 `{eb004a00-9b1a-11d4-9123-0050047759bc}\26`、IPv6 `{eb004a01-9b1a-11d4-9123-0050047759bc}\26`）の削除権限を検査します。
- 読み書きは可能で削除だけが拒否され、所有者が Administrators、保護された正規順の Allow ACE だけの DACL で、既存権限で DACL を変更できる場合に限り、Administrators へこのキーだけの非継承 DELETE を追加し、変更前後の権限を読み戻します。既存の ACE・所有者・グループ・保護状態は維持し、拒否 ACE・特殊 ACE・別所有者などは補完せず失敗として記録します。全ハンドルを閉じてから通常の netsh reset を実行し、キーが再生成される場合も次回は同じ検査を行います。
- netsh reset は全項目の成功後も `ERROR_SUPPRESS_OUTPUT`（15017）を返し、netsh はこれを終了コード 1 に変換します。完了と判定するのは、終了コード 1・stderr 空で、全 34 項目の成功と再起動案内が System32 の netiohlp リソースから作る全文に一致し、カテゴリ順と空のカテゴリ名も照合できた場合だけです。リソースの形式が未知、出力の欠落・追加、エラーがある場合は失敗のままです。生の終了コードは保持し、完了判定を別に記録します。それ以外の非 0 は失敗として記録しますが、その場合も IPv6 のリセットと後続の再設定へ進み、全体を成功とは表示しません。反映には引き続き PC の再起動が必要です。
- 旧版の IP 退避情報は設定読込時の未使用フィールドとして無視し、起動時の復旧・復元ボタン・復旧待ちの操作制限は設けません。

## 期限と中断

- 各外部処理は 120 秒で中断を要求し、IPsec・WINS の条件付き処理は 45 秒で中断を要求します。この期限は呼び出しが戻るまでの上限ではありません。
- タイムアウト・例外・終了不明の場合だけ `RequiresOperationAbort` でおまかせ・手動一括の後続の変更を止め、PC 再起動後のやり直しを案内します。子プロセスが終了要求に応じない場合は、実際に終了するまで処理中状態と変更操作の排他を保持します。

## Winsock・WinHTTP

- Winsock は SPI で非表示・単独 LSP を含む登録を列挙し（64 ビット OS では 32 ビット側も）、両カタログの全件が基底プロバイダーの場合だけリセットします。LSP があれば保護して省略し、確認不能は失敗として残します。手動メンテナンスの Winsock リセットは従来どおりです。条件付き修復は送信自動調整・TCP/NIC 設定より前に実行します。
- WinHTTP は `WinHttpResetAutoProxy` のキャッシュ専用フラグ `0x2000C` だけを使い、保存済みプロキシ設定を書き換えません。同一サービス内の試行間隔は 30 秒以上とし、受付直後の再実行は省略、前回失敗直後は未完了と表示します。API の受付結果と実際のキャッシュ消去は区別し、消去は実測しません。

## IPsec・WINS

- IPsec は Main Mode と Quick Mode の両 SA を取得できた後、Quick Mode、Main Mode の順に削除要求します。保存済みの IPsec 規則・認証設定には触れず、対象なし・未対応は理由付きで省略します。取得失敗や一部削除後の失敗は成功にしません。SA は再確立され得るため、空であることを完了条件にしません。
- WINS は DHCP 再取得後、IP が有効で NetBIOS を無効にしていない NIC に有効な WINS 構成がある場合だけ `nbtstat -RR` を実行します。構成の確認失敗と対象なしを区別し、終了コードを保持します。

## DHCP

- IPv4 は DHCP 有効時、IPv6 は有効な取得済み DHCPv6 リースがある場合だけ処理します。名前・GUID・InterfaceIndex が一致した選択 NIC に限り、固定 IP の NIC は解放しません。利用状態が不明な NIC も解放せず、確認不能の失敗結果として残します（既知の対象外として成功表示しません）。
- 解放は 15 秒、更新・回復は独立した 60 秒の期限を持ち、解放が失敗・キャンセルしても更新を試みます。更新後は DHCP 由来の有効な IP と既存のデフォルトゲートウェイの回復を確認し、不明・未回復は失敗として残します。

## 適用後の読み戻し

- 同じリース内で BBR2、RSS 有効・RSC 無効、Fast Open 有効、Internet の ECN・timestamps 有効、受信ウィンドウ、`int tcp dump` の `set global` 行にある `pacingprofile=always` を読み戻します。ポリシー上書きや不完全な取得は成功扱いしません。
- RACK/TLP は日英の既知ラベルで両方の有効状態を確認できた場合だけ変更不要とし、未確認・無効なら設定コマンドの結果を保持します。Fast Open fallback と UDP などはコマンド受付結果だけです。
- 読み戻しが保証するのは保存された構成で、各接続の実際のペーシングや遅延ではありません。
