# ネットワーク操作

自動最適化を先頭・初期表示にし、適用項目は ON/OFF・削除・既定化などの一覧で示します。処理中はタブとログを含む通常コンテンツを無効にし、進捗と処理段階を全面表示します。各画面の実行状態とコマンド完了通知でロックを解除し、利用者の閉じる操作だけを処理中に止めます。キャンセル可能な Ping 測定中は、全面表示に既存の中止コマンドを公開します。更新・OS 終了などの終了経路は妨げません。

各操作は ViewModel が共有ゲート `INetworkMutationGate` のリースを取得し、service が生成したコマンドを executor が実行します。実行の流れとゲートの範囲は[主要コンポーネント](architecture.md)、記録の形式は[設定の保存とログ](data-model.md)を参照してください。

## Windows の主な操作

- **おまかせ高速化設定**: 最初の設定変更前に起動境界と起動指紋を保存し、設定後に DNS キャッシュ・名前解決・NRPT・hosts を検査します。境界や指紋を取得・保存できない場合は変更を始めません。起動時の再確認は[起動](workflow.md)、検査の詳細は[ネットワーク診断](troubleshooting.md)にあります。
- **実行順**: 同じリース内で、IPv4・IPv6 のスタックをリセットした後、IPsec の確立済み接続状態を破棄し、条件付き Winsock リセットと WinHTTP 自動プロキシキャッシュ消去、選択 NIC の DHCP 解放・再取得、DNS、許可リスト化されたキャッシュ処理と UDP オフロード既定化・PCI Express 省電力の AC 時無効化、TCP 既定化と BBR2・RACK/TLP・RSS 有効化、RSC 無効化、選択物理 NIC のゲーム向け設定、切断済みデバイス整理を順に実行します。WINS の再登録は DHCP 再取得の後に行います。接続名を参照する処理が終わった後にだけ名前整理を行います。外部コマンドと API の判定・期限は[OS コマンドと API の契約](api-reference.md)に示します。
- **ゲーム向け NIC 設定**: 共通項目と媒体別の許可リストは[ゲーム向け NIC の詳細設定](gaming-nic-settings.md)、電源関連は[電源管理](power-management.md)にあります。
- **TCP 設定**: 低遅延向けの採用方針と適用条件は[低遅延を優先する設定方針](configuration.md)、ペーシングと ACK 頻度の判断は[採用済みの設計判断](design-decisions.md)にあります。`TcpAckFrequency=1` は、選択 NIC が既定経路の回線で上り容量 10Mbps 未満と 30 日以内に計測済みの場合だけ省きます（`UplinkAckPolicy`）。
- **ルート表**: PC 全体のルート表のクリア（`route /f`）は既定経路を含めて通信を断つため、おまかせの対象外です。手動メンテナンスでは引き続き選択できます。
- **上り速度の制限**: おまかせ高速化設定とは独立した画面で、計測・適用・解除を利用者が個別に行います。詳細は[上り速度の制限](uplink-limit.md)にあります。
