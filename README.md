# Shisui

Shisuiは、DNSの切り替え、通信状態の診断、Windowsのネットワーク設定の調整を、ひとつの画面から行えるデスクトップアプリです。

設定に詳しくない場合は「おまかせ高速化設定」、自分で確認しながら使いたい場合は各機能を個別に実行できます。

> **ご注意**
> Shisuiは、ネットワークアダプターやWindowsの通信設定を変更します。実行中に一時的に通信が切れることがあります。
> 起動時に管理者権限を要求します。

## ダウンロード

[Shisuiの最新版をダウンロード](https://shisui.kagayoi.com/Shisui-win.msi)

ダウンロードしたMSIを実行してインストールしてください。以後の更新はアプリ内から適用できます。

旧インストーラー版を利用している場合は、起動時の案内に従って最新版へ移行できます。設定とログは引き継がれます。

## 主な機能

- **DNSの切り替え**
  Cloudflare、Google Public DNS、Quad9、NextDNS、任意のIPv4／IPv6アドレスを選択できます。いつでも自動取得（DHCP）へ戻せます。
- **DNSキャッシュのクリア**
  古い名前解決情報を削除します。
- **Ping・トレースルート**
  よく使うサービス、任意のホスト名、IPアドレスへの通信状態を確認できます。4・30・100回の測定と中止に対応し、Windowsでは損失率・最小／平均／最大・p95・ジッターを表示します。
- **ゲーム優先・有線／Wi-Fiの低遅延設定（Windows）**
  対応するNICのRSS・LSOv2・IPv4 IP/TCP/UDPおよびIPv6 TCP/UDPのチェックサムオフロードも有効にし、変更前の値を保存します。設定値の確認とゲーム遅延の実測は別です。
  有線は割り込み調整とEEEに加え、Realtek製NICでは対応しているグリーンイーサネット・Gigabit Lite・Power Saving Modeも無効化します。Wi-Fiは対応する割り込み調整と省電力関連設定を無効化します。CPU負荷・消費電力が増える場合があり、改善は保証されません。おまかせ高速化設定に含まれ、適用後はPCの再起動が必要です。
  Realtek製有線NICのデバイスの電源オフ設定も、確認済みドライバーや対応する電源管理機能で無効化します。設定できない場合や復元情報と競合する場合は結果に表示します。保存値の確認と稼働中の反映確認は別です。
- **アダプター情報の確認**
  MACアドレスやリンク速度を表示します。
- **おまかせ高速化設定**
  DNS、低遅延向けのNIC・TCP設定、キャッシュ処理と通信設定の修復をまとめて実行できます。変更範囲と注意点は[設定をおまかせしたい場合](#設定をおまかせしたい場合)を参照してください。
- **暗号化DNS**
  対応するDNSでDoH（DNS over HTTPS）とDoT（DNS over TLS）を切り替えられます。
- **BBR2・TCP設定**
  BBR2、RACK/TLP、受信ウィンドウ自動調整、RSC、ECN、RSS、TCP Fast Openなどを個別に設定できます。TCP ACK頻度は選択したアダプタへ値1を適用し、現在の設定値の確認とWindows既定への復帰もできます。ACK頻度の変更後はPCを再起動してください。
- **MTUの復元**
  変更されているIPv4／IPv6のMTUを標準値の1500へ戻せます。
- **ネットワークメンテナンス**
  PCI Express・Wi-Fi省電力のAC時無効化、保存したWi-Fi電源設定の復元、UDPオフロードの既定化、IPアドレスの再取得、各種キャッシュのクリア、プロキシ・Winsock・TCP/IP設定のリセットなどを実行できます。
- **使い込んだPC向け診断**
  パケットエラー、古いドライバー、問題のあるネットワークデバイス、過去の高速化設定などを読み取り専用で確認します。
- **接続名の連番を整理**
  Windowsが切断済みと判定したネットワークデバイス登録をまとめて削除し、「イーサネット 2」などの連番を外せます。セーフモードなどでアダプター一覧が空でも削除できます。
- **自動更新**
  起動時または手動で最新版を確認し、アプリ内から更新できます。

## おすすめの使い方

### 設定をおまかせしたい場合

1. 起動時に表示される「自動最適化」で、使用中のネットワークアダプターを選びます。
2. 「おまかせ高速化設定」を実行します。
3. PCを再起動します。

Windowsでは、次の設定と修復をまとめて行います。

- 最初にIPv4・IPv6のIPスタックをリセットし、続けて下記の設定を適用します。リセット前の固定IP・静的経路・DNSなどの退避・復元は行いません。保存キーで管理者の削除権限だけが不足する場合は、対象キーの権限を限定して補完します。
- リセット後、選択したNICのDHCPアドレスを再取得し、DNSをCloudflareの標準DNSへ変更してDoHを有効にします。DHCPで取得していないアドレスは再取得処理の対象外です。再取得に失敗した場合は実行ログを確認してください。
- DoH登録の欠落・不整合を修復し、既存の平文DNSへの切り替え禁止設定を維持します。証明書やTailscaleの設定は初期化しません。登録値の確認は暗号化通信の成功を保証するものではありません。
- 設定後にDNSキャッシュを再構築し、名前解決・名前解決ポリシー・hosts・今回のDNSエラーを確認します。失敗や確認不能は実行結果に残します。設定変更前に再確認待ちと起動指紋を保存できなければ処理を開始しません。確認待ちが残った場合、PC再起動を確認した後のアプリ起動時に再検証し、正常確認と解除の保存が成功した場合だけ待ちを解除します。保存失敗時の自動再確認は保証しません。[検証と修復の設計](DESIGN.md#ネットワーク操作)を参照してください。
- TCP設定を初期化したうえで、BBR2・TCP損失回復（RACK/TLP）・RSS・ECN・timestamps・Fast Openとfallbackを明示的に有効化し、RSCを無効化します。既定値への回帰より低遅延を優先する方針です。OSのUDP URO/USOは既定化し、対応する選択NICのUROは無効化します。大量受信時のCPU負荷が増え、受信速度が下がる場合があります。
- PC全体のTCPペーシングを`always`にします。選択NICの媒体で適用を分けず、送信を平滑化してキュー圧を抑える機構を優先した選択で、BBR2を必須条件とはしません。有線での比較計測では中央値の一貫した改善は確認できず、遅延改善量は保証しません。
- 旧ACK/Nagle設定の初期化後、選択NICの`TcpAckFrequency`をDWORDの1に設定し、設定値を読み戻して確認します。TCPの受信確認を受信1セグメントごとに返す設定です。ゲームやpingの改善量は未測定です。
- ECNは対応経路での輻輳通知、timestampsはRTT計測、Fast Openは対応アプリ・接続先でのTCP通信開始の短縮に使います。UDPゲームのping低下を保証する設定ではありません。適用後はECN・timestamps（Internet）とFast Openの有効状態も確認します。[採用理由と適用条件](DESIGN.md#低遅延を優先する設定方針)を参照してください。
- 選択した物理NICに[ゲーム向け設定](#ゲームの遅延を優先したい場合)を適用します。
- 現在の電源プランのPCI Express省電力を電源接続時（AC）だけオフにし、Wi-Fiを最大パフォーマンスにします。バッテリー時の値と他の電源プランは変更しません。PCI Express機器全体に影響し、消費電力・発熱が増える場合があります。Wi-Fiの変更前の値は保存され、同じ電源プランを選んでメンテナンスから復元できます。
- Winsockの全登録を確認し、通信機能の拡張（LSP）がない場合だけリセットします。LSPがある場合は保護して省略し、確認できない場合は未実施のエラーを表示します。WinHTTPの自動プロキシキャッシュの消去を要求しますが、保存済みプロキシ設定は変更しません。
- 設定変更の前に、確立済みのWindows IPsec接続状態を破棄します。IPsecの規則は変更しません。WINSを利用している場合は、DHCP再取得後にNetBIOS名を再登録します。対象がなければ省略し、確認・実行の失敗はログに残します。
- 切断済みデバイスの登録と接続名の連番を整理します。PC全体のルート表のクリアはおまかせ設定では実行しません。設定の反映にはPCを再起動してください。

リセットの一部が失敗しても、処理が終了していればエラーを実行ログへ残して再設定を続けます。タイムアウトなどで終了を確認できない場合は後続の変更を停止します。PCを再起動してから、おまかせ高速化設定をやり直してください。

MTUとルーターの設定は自動変更しません。適用結果は実行ログで確認できますが、速度や遅延の改善を保証するものではありません。変更範囲や適用後確認の詳細は[設計文書](DESIGN.md#ネットワーク操作)を参照してください。

### DNSだけ変更したい場合

1. 「DNS 設定」を開きます。
2. 使用中のネットワークアダプターとDNSを選びます。
3. 「適用」を押します。

元に戻す場合は「自動取得 (DHCP) に戻す」を使用してください。

### 通信状態を調べたい場合

「ネットワーク診断」で対象を選び、Pingまたはトレースルートを実行してください。

### ゲームの遅延を優先したい場合

1. ゲームで使う有線またはWi-Fiで接続し、「ネットワーク診断」で同じ相手へ100回測定して、損失率・p95・ジッターを記録します。
2. 「自動最適化」で使用する物理NICを選び、「おまかせ高速化設定」でNIC設定と通信設定をまとめて適用します。
3. PCを再起動し、変更前と同じ負荷・同じ相手で複数回測定します。

NICをその場で再起動しないため、適用直後に確認できるのはドライバー設定として保存された値までです。稼働中の反映や性能の確認ではありません。
NICの変更前の値とWi-Fi電源設定の元の値はアプリの設定ファイルへ保存されます。Wi-Fi電源設定はメンテナンスから復元できます。
Wi-Fiは、標準の割り込み調整・RSS・対応オフロードと、対応するMediaTek製PCI無線NICの省電力設定が対象です。
MediaTek RZ616では、ドライバーが対応値を公開するA-MSDU送信（`AMSDUTx`）だけをOFFにします。送信側の集約を減らす方針で、遅延改善量は保証しません。受信側（`AMSDURx`）は、このドライバーでOFFが集約待ち削減になる機構を確認できないため、現値を維持します。
PCIe接続のRealtekでは、対応するFlow Control・Advanced EEEをOFFにします。UROは標準項目を公開し、ON/OFFに対応する物理NICだけOFFにします。
対応可否は確認済みの媒体・メーカー・設定項目に限定し、他社の独自設定や非対応項目へ同じ値を推測適用しません。
NIC設定の適用処理は、仮想NIC・対象外オフロード・リンク速度・バッファー・周波数帯・チャンネル幅・ローミングを変更しません。PC全体のTCP設定とNIC側のRSS・オフロード設定は別に確認します。
Wi-Fiの省電力無効化は消費電力や発熱、バッテリー駆動時間に影響します。電波やアクセスポイントの問題を直す機能ではありません。
DNSやTCP、その他の設定を元に戻すボタンではありません。

測定はOSの経路選択を使用し、アダプター選択とは連動しません。WindowsのRTTはミリ秒単位なので、微小なNIC内の改善は識別できない場合があります。
ICMPの応答制限による損失はゲーム通信の損失とは限りません。p95は成功応答の95パーセンタイル、ジッターは連続した成功応答のRTT差の絶対値の平均です。
ルーター・回線の混雑による遅延は、このNIC設定だけでは解消できません。測定結果と設定結果はファイルログにも記録します。

## 使用前に確認してください

- 手動メンテナンスの「ルーティングテーブルをクリア」は既定経路も削除するため、通信が切れます。実行後はPCを再起動してください。
- WinsockやTCP/IPのリセット、IPアドレスの再取得では、一時的に通信が切れることがあります。
- 「おまかせ高速化設定」と「接続名の連番を整理」では、取り外し中のUSB LANアダプターやドック内蔵LANも削除対象になる場合があります。再接続時にWindowsが再検出します。
- 無効化されているだけの現役デバイスは、「接続名の連番を整理」では削除しません。
- NextDNSを利用する場合は、NextDNS側で現在のIPアドレスをLinked IPとして設定してください。
- コマンドの成否やエラー内容は画面下部の実行ログで確認できます。DNS名前解決の確認に失敗した場合は、詳細ログに失敗した段階とエラー・例外の情報も記録します。ファイルログにはネットワークアドレスやアダプター名も含まれるため、共有前に内容を確認してください。

## 困ったとき

- **DNS設定が反映されない**
  対象のネットワークアダプターが有効になっているか確認し、「一覧を更新」を実行してください。
- **コマンドが失敗する**
  画面下部の実行ログを確認してください。詳しい診断情報は「バージョン」タブからログフォルダを開いて確認できます（Windowsでは`%APPDATA%\Shisui\logs`）。管理者権限がないと設定を変更できません。
- **アプリの設定を保存できない**
  ログで`%APPDATA%\Shisui\settings.json`の読み込みエラーや書き込み権限を確認してください。読み込みに失敗した場合は元のファイルを保護するため保存を停止します。問題を解消してからアプリを再起動してください。NIC・Wi-Fiの変更前の値が含まれるため、設定ファイルを安易に削除しないでください。DNSなどの適用済みの通信設定は、アプリ設定の保存失敗では元に戻りません。起動時の更新確認と更新スキップの設定は、保存に失敗すると変更前へ戻ります。
- **リセット後に通信できない**
  「要再起動」と表示された操作を実行した場合は、PCを再起動してください。
- **元の設定へ戻したい**
   DNSは「自動取得 (DHCP) に戻す」、TCP設定は各項目の「既定値に戻す」を使用してください。NIC詳細設定はWindowsのアダプター設定から変更前の値へ戻してください。
